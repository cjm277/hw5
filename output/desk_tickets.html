2. For each ticket, how did Actual compare to the Expected plan I wrote earlier?

Across the three tickets, I ended up with Boss-coordinated parallel rounds for delegation instead of the chained hand-offs I was expecting from one agent to the next. This happened because I noticed my one-at-a-time version started taking far longer than it had been on previous runs, so I prompted the AI to run delegations in parallel to increase speed; I did not realize at the time that this could compromise the accuracy/safety of the agent team in favour of speed.

5. Three new problems Campus Customs might face that this agent team could not solve with the tools I built

  1. Funding the 103 restock we want
    • We can't do it because there's no mechanism for recording incoming sales and revenue; cash only decreases with the current team.
    • We would need tools to create a customer order, record payment being received, and create a customer invoice.
    • We would also need an orders table that can record incoming cash.
  2. Restock items after an order
    • We were able to pay invoice 501 under ticket 101, but the resolution never actually ordered the tee-shirt that was being inquired about; and even if we had placed the order, we don't currently have a mechanism to add stock. Our date is also fixed, so we'd never see the order arrive after the lead time had been exhausted.
    • We would need a receiving/procurement agent that could receive shipments and add stock, record the vendor invoice, and advance the shop date.
    • We would also need a SKU-to-vendor table, since Inventory currently guesses the vendor based on its specialty.
  3. Send real communications
    • Currently, our drafts are never sent, both by rule and because they lack the mechanism to do so; the “never contact real vendors” rule means no order can actually be sent to a supplier, and we haven't built the tools needed to do it.
    • We'd need a tool to send messages within Customer Service, which would for safety need the same human approval as payments.
    • We'd also need a tool that can verify that the destination address of the communication matches the vendors and landlord on file, as we are dealing with sensitive information sharing and would want to ensure the email reaches the right place.

Closing reflection

My greatest point of concern in how my agent team actually operated for me, compared to what the professor may have been looking for from this assignment, is the parallel delegations from the Boss that resulted from me trying to make the model faster. I know we wanted to allow the agents to talk to each other and I worry they are not doing that, not because they are not able to, but because the Boss is hijacking the delegation process so they end up never delegating to each other. Earlier test runs show agents handing off to each other (e.g. aef84a47c61c, Accounting → Facilities on 102), so the ability exists; my speed changes suppressed it in the graded run. It also seems like the agent team may have been made less safe/reliable because one agent who was building an output was doing so at the same time as another agent was verifying the legitimacy of the source document. The Actual results are the Actual results, so I am reflecting by characterizing those differences accurately and acknowledging their implications.
